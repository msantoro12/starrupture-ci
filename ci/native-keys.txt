# A line may name where the plugin source holds the number, so the check can
# compare it with the PDB and auto-apply can rewrite it:
#   <plugin> <Class::Member> <file-suffix>:<regex>
# In the regex @ is the number (hex or decimal) and ~ is \s*; see
# ci/apply-proposals.mjs "fixed offsets in the source". Engine-internal
# layouts (TArray, TSharedPtr counts) are engine invariants and are left out.
#
# A line with a class name alone, <plugin> <ClassName> [size] [optional], names an
# unreflected struct the plugin needs the size of. The size is read from the PDB
# and written as a class-key row (the class name as the key, offset 0, mask 0) on
# every build. The word size is for reading; optional is as below. No built
# values, no anchor.
#
# Before the anchor a line may give, in this order:
#   <offset> <size> <mask>  the built values (hex), for a key whose PDB size is
#                           not the plugin's: FTransform::Translation is sized
#                           as the SIMD register there (ci/field-rows.mjs);
#   optional                the plugin has a fallback without the member, so a
#                           member gone on a build gets an absent row and the
#                           plugin takes its fallback. Without it, a member gone
#                           on a build holds the map: the loader refuses a plugin
#                           whose field request does not resolve. A key listed
#                           by several plugins is optional only if every line
#                           says so.
#
# RuptureTimer, WaveOptimiser, CameraControls and ProductionViewer's
# ServerSessionName read their numbers through the loader's map, which holds the
# row per build, so those lines carry no anchor: the member is only compared
# between builds and nothing rewrites the source. RuptureTimer no longer reads
# WaitingDuration or bWaitingForNextWave.
